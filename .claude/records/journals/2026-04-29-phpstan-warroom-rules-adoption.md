## Decisions Made

1. **Option A — Ship Phase 1 narrow, accept AC #6 unmet on predating grounds.** Pre-existing `phpstan-deprecation-rules` baseline on `main` had 4 errors before the package was wired (`bootstrap/app.php:33` deprecated `validateCsrfTokens()`, `config/database.php:64` and `:84` deprecated `PDO::MYSQL_ATTR_SSL_CA`, `config/sanctum.php:85` deprecated `ValidateCsrfToken` class constant). The General authorized Option A: ship the package adoption clean and document AC #6 as not-met-due-to-predating-baseline, rather than bundle a deprecation cleanup into this PR. Reasoning: the Shipping Order's "do not bundle" rule applies more strongly to baseline issues the package didn't surface than to findings the package would surface. A dedicated Shipping Order already exists (`2026-04-30-laravel-137-deprecation-cleanup`) and explicitly enumerates the same 4 errors, with the `MYSQL_ATTR_SSL_CA` item flagged for ADR-level consideration. That work belongs to that permit, not this one. The package adoption stands on its own merits — `git blame` on `phpstan.neon` will read cleanly with one focused commit.
2. **`--no-verify` on commit and push.** The CaptainHook pre-commit gauntlet runs `lint:test → phpstan → deptrac → test:arch`, and the pre-push hook runs the full test suite. The pre-commit hook would fail on phpstan due to the predating baseline, independent of this branch's content. The General authorized a one-time scoped exception specifically for this predating-baseline situation. Documented here for the audit trail. Not to be normalized — every other shift on this warehouse runs the full hook gauntlet without override.
3. **Single commit, no second commit for suppressions.** Step 7 of the Shipping Order conditioned a second commit on Step 3 surfacing findings to suppress. Step 3 found nothing to suppress (all four new rules at 0). The canonical one-commit shape applied.
4. **Did not modify `app/CLAUDE.md` warehouse regulations.** Step "Not on This Pallet" item flagged this as conditional on whether the docs reference the inline `ConnectionTransactionReturnTypeExtension`. A `grep` of `app/CLAUDE.md` confirmed no reference (the regulations describe the rule — "Use `$this->connection->transaction(Closure)`" — not the inline extension class). Nothing to update.
